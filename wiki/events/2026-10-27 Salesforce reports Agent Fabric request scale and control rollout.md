# Salesforce reports Agent Fabric request scale and control rollout

Salesforce says Agent Fabric handles more than 1.2 billion requests daily. The company announced continuous agent and API evaluations, automated interventions, discovery for internal and third-party environments, federated gateway policies, and spending controls. Its kill switch, open policies, FinOps dashboard, model wallet, and cost-optimization policies are generally available; Agent Evals and API Evals are scheduled for beta in November 2026 and general availability in January 2027.

ASICS Digital is helping shape the Agent Evals beta. Capita, GE Appliances, and Newell Brands describe using Agent Fabric as a control plane or building toward governed agent operations. These named statements establish operator interest and use context, but not paid attach, contract expansion, or measured customer outcomes.

## Commercial evidence gate

This is scaled traffic and trust-control readiness evidence, not a new monetization green shoot.

- **Payer:** an enterprise using Salesforce or MuleSoft is the prospective payer, but the release does not identify who pays specifically for Agent Fabric or the new controls.
- **Toll-gate mechanism:** a control plane spanning discovery, registry, policy enforcement, evaluations, kill switches, API governance, budget limits, and cost optimization.
- **Metric, period, and denominator:** more than 1.2 billion requests handled daily. Salesforce does not define the request population, customer count, active-agent count, agent share, or measurement window beyond the daily rate.
- **Revenue bridge:** Salesforce has previously disclosed Agentforce ARR, but this release does not connect Agent Fabric traffic or controls to price, ARR, ACV, backlog, paid attach, bookings, recognized revenue, renewal, or margin.
- **Repeatability and maturity:** daily request volume is recurring platform activity. Several controls are generally available, while Agent Evals, API Evals, triggered intervention, and the custom scanner remain beta or future general availability.
- **Attribution quality:** high for primary operator traffic and availability statements; medium for customer adoption because the named quotations do not disclose deployment scope or commercial terms.
- **Still unproven:** active customers and agents, request mix, control interventions, evaluation pass rates, prevented incidents, realized cost saving, pricing, paid attach, retention, attributable revenue, and margin.
- **Strongest falsifier:** the request count largely reflects conventional API or non-agent traffic, customers do not adopt or pay for the controls, or automated intervention fails to improve quality and cost in production.
- **Next verification trigger:** active-agent and customer counts, agent-request segmentation, control-event and incident outcomes, paid attach, price, ACV, renewal, attributable revenue, and customer-measured unit economics.

The stated token reduction of up to 75% comes from test scenarios and is not a production customer-economics result.
