What the constrained codes mean

These responses suggest a request met an access control, but the code alone does not reveal the publisher's intent.

401 · Authentication required
The request did not provide valid credentials.
403 · Access refused
The server understood the request but did not authorize it.
429 · Rate limited
The requester sent too many requests within the server's limit.
404 · Not found
A missing resource; shown under other client errors, not the constrained proxy.
Only 401, 403 and 429 are grouped as an access-constrained proxy. Redirects and ordinary client errors remain separate.

Evidence ladder

Each step separates measurement from inference.

  1. DemandCompare identified requests with the preceding period.
  2. IntentSeparate Training, Mixed Purpose, Search and User Action.
  3. Publisher responseDistinguish served, redirected, constrained and failed requests.
  4. OperatorsMeasure whether traffic comes from identifiable counterparties.
  5. Identity and transaction readinessInspect exposed controls and protocols.
  6. Returned publisher valueNot measured by Radar. Attribution, conversion, revenue, licensing and serving-cost data are required.
1

What Radar observes

Identified request activity, classified intent, HTTP outcomes, operators and exposed readiness checks.

2

What it may mean

Growing or training-led demand can increase pressure on publishers and make traffic governance more valuable. It does not establish extraction or harm.

3

What would confirm or change the thesis

Attributable referral, task completion, net-new demand, revenue, paid access, licensing and serving costs must be connected.
